# Status

0.17.0 is the latest release; each release carries a prebuilt binary for Linux x86_64
([changelog](https://github.com/beyond10x/modelspec/blob/main/CHANGELOG.md)). 0.1.0 was
milestone M0, the semantic core. `modelspec train --backend vulkan` trains on one Vulkan device
within the GPU tolerance of the CPU reference since 0.4.0, and since 0.6.0 it writes and resumes
checkpoints there, `modelspec infer --backend vulkan` runs a checkpoint on the device, `modelspec
compile` writes a sealed artifact directory and `train --record` with `observe` records and
replays a run. A binary built without the `vulkan` feature refuses that backend with
`E-TARGET-001`.

| Release | What it added |
|---|---|
| 0.7.0 | `train --backend vulkan` refuses a diverged run with the CPU run's `E-TRAIN-001`; the plan verifier is bounded on an untrusted artifact; a matmul kernel's module id covers its tile; `--ui ui/dist` serves the observatory UI; a run's events carry parameter and gradient statistics on sampled steps |
| 0.7.1 | every dispatch of a plan has a FLOP and a byte count that `ir --stage kernel` and `train --backend vulkan --profile` print; the Vulkan descriptor pool counts every view a dispatch reads and writes |
| 0.8.0 | a CPU run prepares its step once; a diagnostic's position is found by binary search; per-step device counters under `--stats` and `--profile`; every benchmark run on the [Benchmarks](/docs/benchmarks) page |
| 0.9.0 | a register-blocked matmul for large outputs; a transposed matmul operand read in place; opt-in `--fast-math` |
| 0.10.0 | `i32` row ids and the operators `embedding`, `add_rows`, `gelu`, `layer_norm`, `softmax` and `attention` on the CPU interpreter; `zeros()` and `ones()`; deterministic fused multiply-adds in every reduction; scheduling for a device profile; elementwise chains as one dispatch; pipeline statistics under `--profile`; `modelspec data prepare`, `data tokenizer` and `data pack` |
| 0.11.0 | `cross_entropy` and `dropout` on the CPU interpreter; `train --backend cpu --data` on a packed directory; held-out evaluation during training with `--eval-every`; the observatory UI loop's gates and ratchet in `task ui-ux` |
| 0.12.0 | `optimizer = adamw(...)` on the CPU interpreter, with decoupled weight decay and a learning rate warming up linearly from 0 and decaying linearly to 0 at the last step; `E-TYPE-023` and `E-TYPE-024` for out-of-range arguments; `E-TRAIN-001` on a non-finite moment; a resumed AdamW run refused |
| 0.13.0 | a `relu_grad` whose gradient operand is a matmul output nothing else reads is an epilogue of that matmul in the Vulkan plan (`epilogue ReluGrad`), so the MNIST step plan has 9 dispatches, 6 barriers and 12 buffers; the `mse` loss sum is recorded beside the largest matmul it can share a barrier interval with; every bit of the losses, parameters, checkpoints and predictions is unchanged |
| 0.14.0 | Vulkan kernels for `embedding`, `add_rows`, `gelu`, `dropout`, `layer_norm`, `softmax` and their gradients, one dispatch each with every sum in the CPU interpreter's order; `EmbeddingGrad` adds without atomics, so two runs give the same bits; the `dropout` mask is computed by Philox4x32-10 on the device and is bit-equal to the CPU's; `train --backend vulkan` trains a matmul, `add_rows` and `gelu` model within the GPU tolerance of the CPU run; a device run of a model with `dropout` is still refused with E-TARGET-011 |
| 0.15.0 | `optimizer = muon(...)` on the CPU interpreter: each rank-2 parameter that no `embedding` reads as its table trains with Nesterov momentum orthogonalized by quintic Newton–Schulz steps, every other parameter with AdamW; `E-TYPE-025` for a `momentum` outside [0, 1) and an `ns_steps` outside [1, 10]; `train --checkpoint` and `--resume` refuse a Muon run; `E-TRAIN-001` on a non-finite Newton-Schulz norm or buffer |
| 0.16.0 | `examples/bert_tiny.mspec`, BERT-tiny with 2 post-layer-norm encoder layers, hidden 128, 2 heads, feed-forward 512, sequences of 128 and the 8,192-token vocabulary (1,486,720 parameters), passes `modelspec check` in `task check-examples`; its hidden-32 twin passes a finite-difference check of every parameter in `f64` and trains to identical `step` and `eval` lines twice from one seed with `train --backend cpu --data --eval-every`; `train --data` on a packed directory refuses with `E-DATA-006`, before the first step, an `embedding` table or `cross_entropy` logits whose size is not the packed `vocabulary_size` |
| 0.17.0 | Vulkan kernels for `attention` and its gradients `AttentionGradQ`, `AttentionGradK` and `AttentionGradV`, for `cross_entropy` and its gradient `CrossEntropyGrad`, and for the `Sqrt` and `Div` of the AdamW update, one dispatch per op with every sum in the CPU interpreter's ascending order, each within the GPU tolerance of the CPU interpreter on the RTX 3090; `train --backend vulkan --data <dir> --eval-every <n>` trains the hidden-32 BERT twin with dropout and AdamW, one host wait per step and the evaluation in the step's command buffer, every step and eval line and every final parameter within the run tolerance of the CPU run, and streams them with `--serve` and `--record`; `train --backend vulkan` no longer refuses a model with `dropout`, while `infer --backend vulkan` on one and `muon` still answer E-TARGET-011 |

## Every capability

**Shipped** means a test or task in the repository holds it, the row names that test or task, and
`task ci` runs it on every change; a test that needs a Vulkan device is built by `task ci` and run
with `--ignored` on a machine that has one. **Planned** means it is a piece of work in the
repository's planning store and not built ([Roadmap](./roadmap.md)). The table is generated by
`modelspec-docs` from its list of capabilities, and `task docs-check` fails when the test a row
names, or the planning record a planned row rests on, no longer exists.
