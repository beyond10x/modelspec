# Wave m0: the M0 semantic core

- Epic: `epic:m0-semantic-core`; every unit `serves` `vision:modelspec`.
- Approval: the directing session approved the wave, its unit commits, the merges and the merge to
  `main` on 2026-10-21, with one implementor at a time. Its push of `main` after the close is
  approved separately. No tag, no release.
- Rules: `aep:implementing` skill 0.23.2, wave mode. Selection read from
  `aep plan artifact waves` (aep 0.74.0) over typed scope entries cited from each story's
  "Lands in" section.
- Integration branch: `wave/m0`, from `main` at `2e6fff5`. Managed tree id `modelspec-wave-m0`.
- Units run one at a time in dependency order. Each `impl/<slug>` forks from the head of `wave/m0`
  after the previous unit merged, so each unit builds on the merged work of the ones before it. The
  collisions below are on files the later unit extends after the earlier unit merged.
- Builds: every cargo command runs through `b10x-build-slot`; full test runs use
  `CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=line-tables-only`. Each tree builds into its own
  `target/`.
- Commits this approval covers: one per unit, the merge of each unit into `wave/m0`, the closing
  store commit, the merge of `wave/m0` into `main`.

## Resume

- Next: unit 3 `m0-parse-subset`. Create its tree from the head of `wave/m0`, write its brief
  beside unit 1's (`~/.cache/modelspec-wave-m0/<slug>/brief.md`, same shape, base = that head),
  dispatch one implementor, then one adversary.
- Per unit after the adversary: record its report verbatim as
  `review-result:adversary-<slug>-pass-<n>` from `.engineering/drafts/`, route introduced findings
  back to the same implementor, record `review_outcome` and `verification` evidence on the story,
  write back scope for new files, commit the unit in its tree through the bot, commit the store on
  `wave/m0`, merge.
- The bot route stops `merge --no-ff` before committing; finish it with
  `b10x-gates bot --repository beyond10x/modelspec -- commit -q -F <mktemp file>`.
- Unit trees stay until the close; teardown then is `worktree finish --discard-cache --archive`,
  `worktree gc --apply --id <tree>`, and branch deletion through the bot.
