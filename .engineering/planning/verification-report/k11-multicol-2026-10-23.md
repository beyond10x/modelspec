# k11 with several output columns per invocation is slower, not faster

The wave m1-h unit 3 implementor measured on 2026-10-23, RTX 3090, P0 1950 MHz, no other compute
process. Base: main 24e84d0. The prototype was not merged. It is kept as
`prototype-multicol-with-probes.patch` in the implementor's scratch directory outside the
repository.

## Base

`train --backend vulkan --profile`, 3 runs of 144,000 steps after a warm-up:

| site | run 1 | run 2 | run 3 | median |
|---|---|---|---|---|
| k11 `d7d3124e` (dW1, `[784,100] x [100,64]`, 196 workgroups) | 4.731 | 4.681 | 4.716 | 4.716 |
| k0 `5666286c` | 8.770 | 8.904 | 8.765 | 8.770 |

## Several columns per invocation

About 30 variants were measured, 2 profiled runs each, against the default tile measured in the
same session. Every variant kept the 1,800-step sha256 `b9bb028a…`.

| k11 variant (workgroup, block cols, rows, depth, ahead, cols/invocation) | k11 µs | default, same session |
|---|---|---|
| 128,16,2,16,2,2 | 4.78 / 4.82 | 4.64 / 4.66 |
| 64,16,2,16,2,2 | 4.83 / 4.77 | 4.64 / 4.66 |
| 128,32,2,16,2,2 | 5.01 / 4.92 | 4.64 / 4.66 |
| 64,16,2,16,2,4 | 6.43 / 6.65 | 4.64 / 4.66 |
| 128,32,4,16,1,2 | 5.99 / 5.98 | 4.71 / 4.70 |
| 112,16,3,16,2,1 (152 workgroups) | 4.70 / 4.67 | 4.72 / 4.69 |

With 2 columns per invocation, k0 measured 12.9 to 13.8 µs, against 8.7 µs for the default.

## Where the time goes (probe builds of k11)

| built with | µs |
|---|---|
| everything | 4.72 |
| no products after tile 0 | 4.37 |
| global loads replaced by constants | 3.37 |
| both | 2.31 |
| only `a` loads replaced | 4.43 |
| only `b` loads replaced | 4.29 |

- Arithmetic is about 0.35 µs of k11. Several columns per invocation reduces only that part.
- The global fetch and barrier chain is about 1.35 to 2 µs.
- Inferred, not measured: L2 reads limit k11. The remaining options are split-K, reading the
  transposed operand strided, and cooperative matrices.
