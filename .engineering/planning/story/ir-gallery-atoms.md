# IR gallery section on the site, with one entry per registry operator

## Context

`epic:ir-svg-gallery` (Outcome, Levels table row "atom"): the documentation site gets its own
section that shows the IR as SVG, arranged like a UI component library, starting with one entry
per atomic element: each operator of the registry, its inputs, output, shapes and dtype, plus its
gradient rule. This story opens that section on the site and fills its first level. It draws
through the renderer of `story:ir-gallery-renderer`.

The registry is `modelspec_core::resolve::OPERATORS` (`crates/modelspec-core/src/resolve.rs:62`,
nine operators). The operator reference page already types an accepted example per operator
(`EXAMPLES` in `crates/modelspec-docs/src/operators.rs:28`); the atom entries use the first
accepted operand shapes of that list, so both pages show the same shapes and an operator with no
example fails generation. The gradient rule is `modelspec_core::ops::gradient`
(`crates/modelspec-core/src/ops.rs:197`), the function autodiff calls, driven through the public
`GradientSink` trait (`crates/modelspec-core/src/ops.rs:162`) by a sink in `modelspec-docs` that
records into a `TensorProgramBuilder`.

## What it adds

- A generated directory `website/docs/gallery/`, registered in `fn outputs`
  (`crates/modelspec-docs/src/main.rs:207`) as an exclusive `Output`, so `task docs-generate`
  rewrites it and `task docs-check` (inside `task ci`) fails on a missing, stale, hand-edited or
  stray file there, SVG files included. Pages and SVG files sit side by side and every page embeds
  its diagrams with a relative Markdown image (`![...](./atom-matmul.svg)`); no SVG is written by
  hand and none goes under `website/static/`.
- `index.md` (generated): the gallery landing page, naming the three levels and linking the level
  pages that exist.
- `atoms.md` (generated): one section per operator of `OPERATORS`, in registry order, with the
  source call and its typed operands and result, the forward diagram and the gradient diagram, and
  the gradient-table row of `ops::gradient` for it.
- Per operator `atom-<name>.svg`: a program of one `Input` per operand (named `a`, `b`), the op,
  and its result as output. `atom-<name>-gradient.svg`: the same program plus an input `G` of the
  result type and the contributions `ops::gradient` emits for every operand, tagged `forward` and
  `gradient`, with `dA` and `dB` as outputs.
- `website/sidebars.ts`: a category "IR gallery" after "Examples", autogenerated from `gallery`.
- `AGENTS.md`: the rule naming the generated directories adds `website/docs/gallery/`.
- `CHANGELOG.md`: one line under `## [Unreleased]`.

## Domain relations

- Gallery page to its SVG files: one page embeds many files, all generated in one run into one
  exclusive directory that the writer empties first. Inferred from
  `crates/modelspec-docs/src/main.rs:273` (`fn write`, `remove_dir_all` when exclusive) and `:245`
  (`fn drift`); no ess/1 document declares it, and none needs to (documentation output).
- Atom entry to registry operator: one entry per element of `OPERATORS`. Inferred from
  `crates/modelspec-core/src/resolve.rs:62`.

## Acceptance

1. After `task docs-generate`, `website/docs/gallery/` holds exactly `index.md`, `atoms.md` and,
   for each of the nine operators of `OPERATORS`, `atom-<name>.svg` and `atom-<name>-gradient.svg`;
   `task docs-check` exits 0, and running `task docs-generate` a second time leaves
   `git status --porcelain website/docs/gallery` empty.
2. Appending one byte to `website/docs/gallery/atom-matmul.svg` makes `task docs-check` exit 1
   naming `stale or edited atom-matmul.svg`; adding `website/docs/gallery/extra.svg` makes it exit 1
   naming `not generated extra.svg`.
3. Test `gallery.atoms.forward` (`cargo test -p modelspec-docs`): `atom-matmul.svg` has nodes with
   `data-op` `Input`, `Input`, `MatMul`, the `MatMul` node `data-shape="[8, 1]"` for operands
   `[8, 4]` and `[4, 1]`; every atom SVG has one non-input node whose `data-op` is that operator.
4. Test `gallery.atoms.gradient`: `atom-matmul-gradient.svg` holds two `Transpose` and two further
   `MatMul` nodes tagged `gradient`; `atom-relu-gradient.svg` holds a `ReluGrad` node;
   `atom-mean-gradient.svg` holds a `BroadcastScalar` node, each as the rows of the table in
   DESIGN.md section 4 say.
5. `task website` exits 0, and the built page `website/build/gallery/atoms/index.html` references
   18 SVG assets and the sidebar of every docs page lists "IR gallery".
6. `task ci` exits 0.

## Out of scope

- The renderer itself (`story:ir-gallery-renderer`).
- Layer and module entries (`story:ir-gallery-layers`, `story:ir-gallery-modules`).
- Internal gradient ops (`ReluGrad`, `BroadcastScalar`) as atoms of their own: they are not in
  `OPERATORS`, and they appear inside the gradient diagrams.
- Diagrams following the site light/dark toggle; the embedded style reads on both.
