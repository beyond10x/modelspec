# IR diagram renderer: deterministic SVG from verified Tensor and Training IR

## Context

`epic:ir-svg-gallery` asks for a component gallery of the ModelSpec IR as SVG, generated by a Rust
crate of this workspace, deterministic to the byte, with no Node, Python or Graphviz at generation
time, and no rendering dependency in `modelspec-core`. Every later story of the epic (atoms,
layers, modules) draws through one renderer; this story builds it and proves it on a fixture, with
no site output yet.

Where it lives: a module of `modelspec-docs`, not a new crate. `modelspec-docs` is the only
consumer, it already depends on `modelspec-core` (`crates/modelspec-docs/Cargo.toml`), and it is
the tool that owns the generated pages and their drift check (`crates/modelspec-docs/src/main.rs`,
`fn outputs` at line 207, `fn drift` at line 245). A new crate would add a workspace member for one
caller. The renderer writes SVG text itself with `std::fmt`; it adds no crate dependency at all, so
`modelspec-core` stays untouched and `task core-no-vulkan` keeps its meaning. If a second consumer
appears (for example `modelspec ir --format svg`), moving the module into its own crate is a later,
mechanical story.

## What it adds

- `crates/modelspec-docs/src/diagram/`: a graph model built from a verified `TensorProgram`
  (`crates/modelspec-core/src/ir/tensor.rs:208`), optionally with the subgraph tags of a training
  program (`TrainingProgram.subgraphs`, `crates/modelspec-core/src/ir/training.rs:66`); a layered
  layout; and SVG emission.
- Layout rule, fixed so the bytes are stable: a node rank is 1 + the largest rank of its operands
  (sources rank 0); nodes within a rank are ordered by `ValueId`; box width is a fixed per-character
  advance times the longest label line (a monospace font is declared, no text measurement);
  every coordinate is an integer; edges are polylines from operand to user.
- Each node is `<g class="node" data-value="%N" data-op="<TensorOp::name()>" data-dtype="f32"
  data-shape="[..]">` (plus `data-subgraph` when tags are given) holding a rect, the op name, the
  type as `TensorType` displays it, and a `<title>` with the line `modelspec ir` prints for it. Each
  edge is `<path class="edge" data-from="%A" data-to="%B" data-operand="i">`. Program inputs,
  parameter reads and outputs are styled apart; subgraph tags get one fill each, from an embedded
  `<style>` readable on a light and a dark page.
- Determinism: no `HashMap` iteration, no float formatting in the output, no timestamp or path in
  the bytes, one trailing newline.

## Domain relations

No `ess/1` document declares a diagram; it is documentation output, not a data contract of
`spec/`. The relations it rests on:

- Diagram node from Tensor IR node: one node per `TensorNode` (one per SSA definition), op, dtype
  and shape from the node. Inferred from `crates/modelspec-core/src/ir/tensor.rs:175`
  (`TensorNode { id, op, operands, ty }`); no ess/1 relation declares it.
- Diagram edge from operand: one edge per entry of `TensorNode.operands`, `data-operand` its
  position. Inferred from `crates/modelspec-core/src/ir/tensor.rs:175`; no ess/1 relation declares
  it.
- Node subgraph tag from `TrainingProgram.subgraphs`: at most one tag per value, one of forward,
  loss, gradient, optimizer. Inferred from `crates/modelspec-core/src/ir/training.rs:33` and `:66`;
  no ess/1 relation declares it.

## Scope

## Acceptance

Each is a test in `crates/modelspec-docs/src/diagram/`, run by `cargo test -p modelspec-docs` and so
by `task ci`, except 5:

1. `diagram.tensor-matches-ir`: the SVG of the Tensor IR of `two_layer_relu.mspec`
   (`CompiledTraining.forward.program`) has exactly one `class="node"` element per definition that
   `modelspec ir --stage tensor` prints for that file, each with that line op and type in
   `data-op` and `data-shape`, and one `class="edge"` element per operand.
2. `diagram.training-subgraphs`: the SVG of `CompiledTraining.training.training` with its tags has
   one node per definition `modelspec ir --stage training` prints, each `data-subgraph` equal to the
   tag that line starts with, and each of `forward`, `loss`, `gradient`, `optimizer` occurs.
3. `diagram.deterministic`: rendering the same program twice, and rendering a clone of it, gives
   equal bytes; the output contains no `.` inside any numeric attribute of `x`, `y`, `width`,
   `height` or `d`.
4. `diagram.layered`: for every edge, the rank of `data-from` is less than the rank of `data-to`
   (read from the `y` of the two nodes), so no edge points upward.
5. `task core-no-vulkan` passes and `git diff --exit-code crates/modelspec-core/Cargo.toml
   crates/modelspec-docs/Cargo.toml` is empty: no crate gained a dependency.

## Out of scope

- Any page, SVG file or sidebar entry on the site (`story:ir-gallery-atoms` and after).
- Kernel IR and execution plan diagrams (epic, Out of scope).
- Interactive diagrams, client-side JavaScript, pan or zoom.
- Edge crossing minimisation beyond ordering by `ValueId`; offered as a later story if a module
  diagram reads badly.
