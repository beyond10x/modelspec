## Rust, numerics and model sizes (R, K)

| Key | Finding | URL |
| --- | --- | --- |
| R1 | Rust's float semantics: "these operations produce results that exactly match IEEE 754-2008"; the rationale notes that this "precludes many transformations, such as turning a*b + c into FMA operations"; on NaN: "IEEE makes almost no guarantees about the sign and payload bits of the NaN", "the result has a non-deterministic sign", "the quiet bit and payload are non-deterministically chosen". | https://rust-lang.github.io/rfcs/3514-float-semantics.html |
| R2 | `f32::mul_add`: "Computes (self * a) + b with only one rounding error"; "guaranteed to be the rounded infinite-precision result. It is specified by IEEE 754 as fusedMultiplyAdd and guaranteed not to change"; the documented example `(1+eps).mul_add(1-eps, -1) == -eps*eps` while the unfused expression gives `0.0`. | https://doc.rust-lang.org/std/primitive.f32.html#method.mul_add |
| R3 | Inner-product error bound `\|fl(xᵀy) − xᵀy\| ≤ γ_n \|x\|ᵀ\|y\|`, `γ_n = (1+u)^n − 1`, Corollary 8. | https://ar5iv.arxiv.org/html/1906.10465 |
| R4 | "C≈6N floating point operators per training token"; "N ≈ 2d_model n_layer(2d_attn + d_ff) = 12n_layer d_model^2 with the standard d_attn = d_ff/4 = d_model", "where we have excluded biases and other sub-leading terms". | https://ar5iv.labs.arxiv.org/html/2001.08361 |
| R5 | GPT-2 small: `vocab_size` 50257, `n_embd` 768, `n_layer` 12, `n_head` 12, `n_positions` 1024. | https://huggingface.co/openai-community/gpt2/raw/main/config.json |
| K1 | Vulkan SPIR-V environment: "Implementations may rearrange floating-point operations using any of the mathematical properties"; "This rearrangement can be prevented for particular operations by using the NoContraction decoration"; denormals "By default any denormalized floating-point value input into a shader or potentially generated" may be flushed; "If shaderDenormPreserveFloat32 is VK_FALSE, then DenormPreserve for 32-bit floating-point type must not be used"; without `SignedZeroInfNanPreserve` "the entry point assumes NSZ, NotInf, and NotNaN"; `OpFAdd`, `OpFSub`, `OpFMul` correctly rounded, `OpFDiv` 2.5 ULP. | https://docs.vulkan.org/spec/latest/appendices/spirvenv.html |
